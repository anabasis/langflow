# 보안

Langflow UI는 IDE이자 코드 실행 플랫폼입니다. 설계상 Langflow UI에는 개발자가 임의의 Python을 작성하고 실행할 수 있는 코드 편집기가 포함되어 있어, 호스트 Langflow 백엔드 프로세스, 파일 시스템, 네트워크에 완전한 액세스 권한을 가집니다.

Langflow는 단일 Langflow 프로세스 내에서 사용자 간 격리를 시행하지 않으며, 로컬 디스크나 네트워크 리소스에 대한 액세스를 제한하지 않습니다. 멀티 테넌트 배포의 경우 Langflow는 애플리케이션 레벨 격리 대신 인프라 레벨 보안에 의존하므로 테넌트 격리를 시행하는 것은 사용자의 책임입니다.

> **경고**: 사용자는 다음에 대한 책임이 있습니다:
> - 포괄적인 인프라 격리 시행
> - LLM 생성 코드나 코드가 포함될 수 있는 사용자 입력을 사용하는 플로우를 포함하여 플로우를 안전하게 실행
> - 저장 중 및 전송 중인 데이터를 포함하여 Langflow 기반 API와 최종 사용자 상호작용의 엔드투엔드 보안 보장

---

## 로컬 개발 중 Langflow 보안

Langflow는 로컬 시스템에 완전한 액세스 권한이 있는 코드 실행 플랫폼입니다. 실행하는 플로우의 안전을 보장할 책임이 있습니다.

Langflow가 신뢰할 수 없거나 LLM이 생성한 코드를 실행할 수 있는 경우 [커스텀 컴포넌트 실행 차단](./block-custom-components.md)을 고려하고 격리되고 컨테이너화된 실행 환경에서 Langflow를 실행합니다.

---

## 퍼스트파티 배포 보안

사용자 또는 조직이 작성한 플로우로 지원되는 API를 제공하는 경우 API 보안을 위해 다음 업계 모범 사례를 따릅니다:

- 인증 및 권한 부여를 제공하는 보안 API 게이트웨이 사용
- 사용자 데이터를 적절하게 격리
- XSS 및 주입 공격에 대한 입출력 살균 (ReDoS 취약점을 방지하기 위한 정규 표현식 패턴 포함)

역방향 프록시 설정에 대한 자세한 내용은 [Nginx 및 SSL로 Langflow 배포](./nginx-ssl.md)를 참조하세요.

---

## 서드파티 배포 보안

제3자에게 Langflow를 서비스로 제공하는 경우 Langflow에서 실행되는 모든 코드가 잠재적으로 악의적일 수 있다고 가정해야 합니다.

Langflow는 테넌트 간 격리를 제공하지 않으므로 인프라 레벨에서 격리를 시행하는 것은 사용자의 책임입니다:

- 프로세스 레벨 격리로 테넌트가 단일 Langflow 프로세스를 공유하지 못하게 방지
- 디스크 레벨 격리로 쓰기 가능한 영구 저장소에 대한 공유 액세스 방지
- 네트워크 레벨 격리로 사설 네트워크에 대한 액세스 방지
- 데이터베이스 레벨 격리로 공유 데이터베이스 리소스에 대한 액세스 또는 수정 방지

인증 및 권한 부여는 Langflow 컨테이너 외부에서 제공되고 시행되어야 합니다.
