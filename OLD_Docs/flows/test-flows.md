# 플레이그라운드에서 플로우 테스트

Langflow의 **플레이그라운드**는 LLM 기반 플로우를 실시간으로 테스트할 수 있는 동적 인터페이스입니다.

플로우가 다양한 입력에 어떻게 응답하는지 테스트하고, 메모리를 검토 및 수정하며, 플로우 출력과 로직을 모니터링할 수 있습니다. 예를 들어, 에이전트 플로우가 다양한 입력에 응답하기 위해 적절한 도구를 사용하는지 확인할 수 있습니다.

**플레이그라운드**를 사용하면 플로우의 로직과 동작을 빠르게 반복할 수 있어 애플리케이션 프로토타입 제작 및 개선이 더 쉬워집니다.

---

## 플레이그라운드에서 플로우 실행

**플레이그라운드**에서 플로우를 실행하려면 플로우를 열고 **Playground**를 클릭합니다. 그런 다음 플로우에 [**Chat Input** 컴포넌트](../components-reference/components-overview.md)가 있는 경우 프롬프트를 입력하거나 음성 모드를 사용하여 플로우를 트리거하고 채팅 세션을 시작합니다.

**플레이그라운드** 보기를 확장하려면 **플레이그라운드** 패인 내에서 **Enter fullscreen**을 클릭합니다.

> **팁**: **플레이그라운드**에 메시지 입력 필드가 없으면 플로우에 **Chat Input** 컴포넌트가 **Language Model** 또는 **Agent** 컴포넌트의 **Input** 포트에 직접 또는 간접적으로 연결되어 있는지 확인하세요.
>
> **플레이그라운드**는 챗봇 및 에이전트와 같은 쿼리-응답 형식의 LLM을 사용하는 플로우를 위해 설계되었으므로, 플로우에는 완전한 **플레이그라운드** 채팅 인터페이스를 지원하기 위해 **Chat Input**, **Language Model**/**Agent**, **Chat Output** 컴포넌트가 있어야 합니다.
>
> 웹훅 이벤트, 파일 업로드, 텍스트 입력 등 다른 유형의 입력이 필요한 플로우는 Langflow API를 사용하여 플로우를 트리거한 다음, **플레이그라운드**를 열어 해당 플로우 실행에 대한 LLM 활동을 검토할 수 있습니다.

### 에이전트 로직 검토

플로우에 **Agent** 컴포넌트가 있으면 **플레이그라운드**에서 에이전트가 사용한 도구와 각 도구의 출력이 표시됩니다. 이를 통해 에이전트의 도구 사용을 모니터링하고 에이전트 응답의 로직을 이해할 수 있습니다.

### 채팅 기록 보기

**플레이그라운드**에서 타임스탬프, 내용, 발신자를 포함하여 플로우의 각 채팅 세션에 대한 메시지 로그를 볼 수 있습니다.

**플레이그라운드** 사이드바에서 검토할 채팅 세션을 찾아 **Options**를 클릭하고 **Message Logs**를 선택합니다.

메시지 로그는 각 채팅 메시지의 `Message` 데이터를 분리합니다. 메시지 로그의 셀을 클릭하면 해당 셀의 전체 내용을 볼 수 있습니다.

### 플레이그라운드에서 메모리 수정

플로우를 디버그하고 테스트하는 데 도움이 되도록 메시지 로그에서 개별 메시지를 편집하거나 삭제할 수 있습니다. 예를 들어 더 이상 플로우의 일부가 아닌 컴포넌트를 테스트하는 동안 보낸 메시지를 삭제할 수 있습니다.

사이드바에서 전체 채팅 세션을 삭제할 수도 있습니다. **Options**를 클릭하고 **Delete**를 선택하면 됩니다.

메모리를 수정하면 채팅 세션을 계속하거나 여러 채팅 세션에서 메모리를 유지하는 경우 챗봇 응답의 동작에 영향을 미칩니다.

**메시지 로그를 편집하면 Langflow의 내부 `messages` 테이블이 편집됩니다.** 이 테이블이 기본 채팅 메모리 스토리지입니다.

## 커스텀 세션 ID 설정

채팅 세션은 세션 ID(`session_id`)로 식별되며, 이는 플로우 실행에 대한 고유 식별자입니다.

기본 세션 ID는 플로우 ID이며, 이는 플로우의 모든 채팅 메시지가 하나의 거대한 채팅 세션으로 동일한 세션 ID 아래 저장됨을 의미합니다.

여러 플로우 실행에서 채팅 컨텍스트를 유지하거나 플로우를 디버그할 때 채팅 세션을 구분해야 하는 경우 커스텀 `session_id`를 설정할 수 있습니다.

커스텀 세션 ID는 여러 이유로 유용합니다:
- 하나의 플로우에 여러 채팅 세션이 있는 경우 채팅 세션을 분리합니다.
- 여러 플로우 실행에서 채팅 세션을 계속하거나 플로우 간에 컨텍스트를 전달할 때 메모리를 유지합니다.
- 동일한 플로우 내에서 여러 사용자의 활동을 구분합니다.
- 디버그 및 테스트 시 자신의 채팅 세션을 식별합니다.

**비주얼 에디터에서 설정:**
1. 커스텀 세션 ID를 설정할 컴포넌트를 클릭합니다.
2. 컴포넌트 인스펙션 패인에서 **Session ID**를 활성화합니다.
3. **Close**를 클릭합니다.
4. 커스텀 세션 ID를 입력합니다. 필드가 비어 있으면 플로우는 기본 세션 ID를 사용합니다.

**Langflow API에서 설정:**

```bash
curl -X POST "http://localhost:7860/api/v1/run/FLOW_ID" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $LANGFLOW_API_KEY" \
  -d '{
    "session_id": "CUSTOM_SESSION_ID",
    "input_value": "message",
    "input_type": "chat",
    "output_type": "chat"
  }'
```

이 명령은 지정된 `session_id`로 새 채팅 세션을 시작하거나 해당 ID로 기존 세션이 있으면 해당 세션을 검색합니다.

## 플로우의 플레이그라운드 공유

> **경고**: **공유 가능한 플레이그라운드**는 테스트 목적으로만 사용됩니다. **플레이그라운드**는 애플리케이션에 플로우를 임베드하기 위한 것이 아닙니다. 애플리케이션이나 웹사이트에서 플로우를 실행하는 방법에 대한 자세한 내용은 [Langflow API로 플로우 트리거](./run-flows.md)를 참조하세요.
>
> **공유 가능한 플레이그라운드**는 Langflow Desktop에서 사용할 수 없습니다.

**공유 가능한 플레이그라운드** 옵션은 `/public_flow/$FLOW_ID` 엔드포인트에서 단일 플로우의 **플레이그라운드**를 노출합니다.

[공개 Langflow 서버를 배포](../deploy/deployment-overview.md)한 후에는 이 공개 URL을 다른 사용자와 공유하여 지정된 플로우의 **플레이그라운드**에만 접근할 수 있게 할 수 있습니다.

플로우의 **플레이그라운드**를 공유하려면:
1. Langflow에서 공유할 플로우를 엽니다.
2. 워크스페이스에서 **Share**를 클릭하고 **Shareable Playground**를 활성화합니다.
3. **Shareable Playground**를 다시 클릭하여 **플레이그라운드** 창을 엽니다.
4. 이 창의 URL을 다른 사용자에게 보내 플로우의 **플레이그라운드**에 접근할 수 있게 합니다.
